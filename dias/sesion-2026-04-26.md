## Setup y errores resueltos

### Backend

- El error `Could not parse SQLAlchemy URL from string ''` venia de `DATABASE_URL` vacio.
- El comando `uvicorn app.main:app --reload` debe ejecutarse desde `backend/`, porque el modulo `app` vive ahi.
- Si se ejecuta desde la raiz, aparece `ModuleNotFoundError: No module named 'app'`.
- Neon requiere URL compatible con SQLAlchemy async: `postgresql+asyncpg://...`.
- Alembic se ejecuta desde la raiz con:

```powershell
backend\.venv\Scripts\alembic.exe -c backend\alembic.ini upgrade head
```

O desde `backend/` con el venv activo:

```powershell
alembic upgrade head
```

### Mobile

- La app usa `EXPO_PUBLIC_BACKEND_URL`.
- `mobile/.env` queda como valor base.
- `mobile/.env.local` se usa para la URL real de ngrok del backend en este PC.
- No se deben commitear secretos ni URLs temporales de ngrok.

### ngrok

- Se instalo/configuro ngrok para poder usar:

```powershell
ngrok 8000
```

- Se configuro authtoken de ngrok en el PC.
- El tunnel de backend y el tunnel de Expo son cosas distintas:
  - `ngrok 8000` expone FastAPI.
  - `npx expo start --tunnel` expone Metro.

### Expo tunnel

- `npx expo start` funciono sin `--tunnel`.
- `npx expo start --tunnel` dio problemas externos/locales de Expo/ADB/ngrok.
- Se detecto un emulador Android fantasma: `emulator-5562 offline`.
- Ese estado hace que Expo intente `adb reverse` y falle aunque se quiera usar el QR/tunnel.
- No parece un bug del codigo de PlotSkip.

### Puerto 8081 ocupado

Si Expo dice que `8081` esta ocupado:

```powershell
netstat -ano | findstr :8081
taskkill /PID <PID> /F
```

O con PowerShell:

```powershell
Get-NetTCPConnection -LocalPort 8081 | Select-Object -ExpandProperty OwningProcess
Stop-Process -Id <PID> -Force
```
